# HLII Interface System

## Direction

Domain: legal sources, legislative journals, court opinions, public records, source freshness, aggregate endpoints.

Color world: paper white, deep ink, muted teal, docket blue-gray, quiet rule lines.

Signature: a civic data surface that treats coverage, freshness, and source limits as first-class product content.

Rejecting: glossy dark dashboard language -> clear public-record interface with restrained cards and report-like hierarchy.

Direction: HLII should feel like a trustworthy legal-source index that is preparing for machine access, not like a finished SaaS analytics product.

## Tokens

- Background: `#f7f9fb`
- Surface: `#ffffff`
- Soft surface: `#eef3f7`
- Text: `#172033`
- Muted text: `#5d6b7f`
- Rule: `#d9e1ea`
- Brand/action: `#1f6f8b`
- Brand hover: `#164e63`

## Components

- Cards use quiet 1px borders, 8px radius, and minimal shadow.
- Buttons use the same 8px-or-less radius and distinguish primary actions by filled teal.
- Tags are plain source labels, not decorative chips.
- Roadmap items should state build order and current limits plainly.

## Content Rules

- Do not imply live full-text search until records are actually exposed.
- Keep the product framed as aggregate public-record tracking.
- Mention MCP as a future interface over bounded read-only endpoints, not as a current auth or platform claim.
